DOCIQ FRONTEND PLAN
====================

Project: DOCIQ
Purpose: Generic AI-powered data analysis tool for a single business deployment.
Important architecture note:
- One DOCIQ deployment belongs to one business.
- Multiple employees/users can securely access the same deployment.
- Different businesses are handled through separate deployments, not a shared multi-tenant UI.
- Dashboard numbers, charts, tables, files, analysis results, and activity are dynamic backend data.
- The reference UI is only a design/layout reference; do not hardcode its sample numbers.

DESIGN SYSTEM
-------------
Primary color palette:
- Mint Whisper: #D1F2EB
- Emerald Green: #50C878
- Royal Amethyst: #0B6E4F
- Dark Evergreen: #013220

Use the palette consistently for:
- Backgrounds
- Navigation
- Buttons
- Cards
- Charts
- Status indicators
- AI analyst components

Visual direction:
- Clean modern SaaS dashboard
- Rounded cards
- Spacious layout
- Professional business/analytics feel
- Responsive desktop/tablet/mobile
- Reference image is the visual direction, not a finished page

Phase 5 — Important Components

PHASE 6 — SECURITY/ACCESS UI
----------------------------
Because each deployment belongs to one business:
- Business/workspace identity
- Employee/user management
- User roles and permissions
- Active sessions
- Logout
- Data-source connection status
- Security/status indicators

PHASE 7 — BACKEND INTEGRATION READY
------------------------------------
Frontend should be designed so hardcoded data can later be replaced by APIs.

Examples:
- Dashboard metrics -> API
- Chat messages -> AI/API
- Data sources -> API
- Analysis jobs -> API
- Reports -> API
- Users/roles -> API

Do not tightly couple UI components to fake/demo data.
